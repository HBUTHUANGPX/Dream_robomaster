> **历史记录，不用于当前启动。** 首次使用请阅读[根目录说明](../../../README.md)和[入门说明](../../../docs/getting-started.md)。

当前交互导航使用 **A* → DWA → PID → 四轮速度执行器**。默认定位仍是 CAD 先验点云与 ICP。FAST-LIO2 的离线输入和运行配置已经准备。官方算法尚未编译和运行，未接入闭环导航。

## 运行

```bash
uv run python -m navigation.server --port 8765
```

打开 http://127.0.0.1:8765 。点击绿色区域。青线为全局路径。橙线为包含 PID 修正的局部预测。白线为估计轨迹。面板显示可用轨迹数。无安全候选时停车。

## 全向运动与 PID

DWA 同时输出底盘坐标中的 `vx`、`vy`、`wz`。机器人可前进、后退、侧移，也可在移动中旋转。平地没有“先把车头对准目标”的阶段。

位置跟踪使用三路独立 PID。纵向误差修正 `vx`。横向误差修正 `vy`。偏航误差修正 `wz`。参考位姿是上一周期已执行局部轨迹的下一时刻位姿。侧向误差不再转换成转向误差。

| 参数 | 纵向 / 横向 PID | 偏航 PID |
| --- | ---: | ---: |
| 比例系数 | 1.4 | 1.8 |
| 积分系数 | 0.16 | 0.08 |
| 微分系数 | 0.06 | 0.06 |
| 修正量上限 | 0.25 m/s | 0.30 rad/s |
| 导数滤波时间常数 | 0.15 s | 0.15 s |

另有底盘速度 PI，用于修正轮速与地面速度之间的偏差。XY 反馈来自激光定位的位移差分和低通滤波。偏航速度来自陀螺仪。轮编码器仅参与定位传播。坡道负载有重力力矩前馈。控制不读取真值位姿。

输出饱和时停止累积使饱和加重的积分。下游限幅时回退该周期的积分。新目标、暂停和停车清除积分及参考位姿。PID 修正后重新检查动态窗口、功率、地形、障碍和制动距离。检查失败时执行安全的 DWA 原指令。

## 三维速度窗口 DWA

每周期采样 `vx`、`vy` 和 `wz`。还加入朝局部目标移动的候选及减速候选。XY 速度和加速度使用向量模长限制，避免斜向速度超过上限。轮速、轮端力矩和电功率也限制可选速度。

| 参数 | 数值 |
| --- | ---: |
| 控制周期 | 0.1 s |
| 恒速预测时域 | 1.0 s，另加完整制动段 |
| 平地指令速度上限 | 1.2 m/s |
| 坡道指令速度上限 | 0.55 m/s |
| 偏航速度上限 | 1.2 rad/s |
| 线加速度限制 | 1.6 m/s² |
| 角加速度限制 | 2.4 rad/s² |
| 制动模型线减速度 | 1.0 m/s² |
| 制动模型角减速度 | 2.4 rad/s² |
| 点云障碍包络半径 | 0.40 m |

指令上限不是实际速度的硬上限。轮地接触、反馈延迟和惯性会造成瞬时超调。实际超速时，动态窗口保留测量速度，并逐步减速。

候选轨迹检查地图边界、通行栅格、高度变化和点云障碍。快速段加密采样。跨对角栅格时检查两个正交相邻栅格。边界保留 0.035 m 跟踪余量。末端加入 XY 向量制动和偏航制动。评分包括路径距离、局部目标距离、独立偏航速度请求、间隙和估计功率，不包含车头对准路径的误差。

默认持续旋转速度为零。接近坡道或检测到持续打滑时，系统允许在行进中小幅调整车身方向，使四轮分担牵引。前进和后退均可，不要求车头朝向目标。此调整在低速时减弱，没有独立的原地调头阶段。用户的非零旋转速度请求优先于该调整。

前视点被地图拐角遮挡时缩短前视距离。被点云障碍遮挡时搜索临时局部目标。持续 15 s 没有位置进展时停车。定位连续失败时也停车。没有障碍速度预测，也没有动态全局重规划。复杂堵塞仍可能失败。

## 方向相关功率

`navigation/power.py` 将底盘速度转换为四轮角速度。每轮上限为 35 rad/s 和 10 Nm。默认电功率预算为 120 W。可用 `--power-budget` 修改预算。

估计公式：`P = sum(max(torque_i * omega_i, 0)) / 0.8 + 0.12 * sum(torque_i²) + 0.003 * sum(omega_i²) + 4`。

单位分别为 W、Nm 和 rad/s。负机械功率不抵扣用电。公式包含堵转损耗。执行层每个 1 ms 物理步统一缩放四轮力矩，使该模型的电功率满足预算。规划层还估计加速度、坡度和方向相关滚动阻力。纵向系数为 0.035，侧向为 0.070。

这些效率和损耗系数是未标定的仿真假设。120 W 是此任务的预算，不代表比赛官方限值。界面显示估计值，不能当作实车功率计读数。

## 打滑时的定位

默认 CAD 先验模式使用点到平面 ICP，法向来自实际赛场三角网格。轮里程计提供初值。地面约束高度。墙面和其他结构约束水平位置。使用稳健权重和四维可观测性检查，避免地面点过多时将轮子打滑解释为水平移动。

没有法向先验的在线建图模式仍使用原有点到点 ICP。两种模式都不是 FAST-LIO。真值仅用于独立误差检查。

## LIO 选择和接入边界

| 项目 | 原始资料 | 本仓库用途 |
| --- | --- | --- |
| FAST-LIO2 | [官方仓库](https://github.com/hku-mars/FAST_LIO)、[官方 MID360 配置](https://github.com/hku-mars/FAST_LIO/blob/main/config/mid360.yaml) | 首选。官方 MARSIM 输入路径适合当前瞬时扫描仿真。 |
| Point-LIO | [官方仓库](https://github.com/hku-mars/Point-LIO) | 后续对比候选。适合评估高动态运动。应核实所选分支的逐点时间和饱和参数。 |

这里的选择基于输入契合度和官方代码，未依据本机精度对比。两者都不能自动替代全局重定位或地图坐标对齐。

当前准备了以下数据：

- 顶部雷达原始点云。点坐标位于雷达坐标系，未使用理想 AHRS 进行水平校正。
- 200 Hz 原始陀螺仪与加速度计。单位为 rad/s 和 m/s²。加速度包含静止时的重力响应。
- 统一仿真时间。点云为 10 Hz 瞬时扫描，不伪造逐点扫描时间。
- 顶部雷达到模拟外置 IMU 的外参：`R=I`，`t=[0,0,0.438] m`。包含实际射线原点的 8 mm 偏移。
- 真值仅写入独立 JSON 文件，用于评估。供估计器使用的 数据包 不包含真值位姿或理想姿态。

这套 IMU 是底盘上的模拟外置 IMU，不是 MID360 内置 IMU 的实测模型。外参不能直接复制到实车。真实 MID360 需要正确驱动、逐点时间、同步、去畸变和标定。第一阶段只给 FAST-LIO 顶部雷达。下方雷达继续用于当前导航感知。

### 导出与回放

ROS 依赖隔离在容器中。以下历史复现需要 Docker、可用的容器网络和至少 12 GiB 的 Docker 存储余量。先按归档环境说明安装 `lio` 依赖组。Python 端使用该依赖组写 ROS1 数据包。当前集成说明位于仓库根目录的 `integrations/fast_lio/README.md`。

```bash
uv run --group lio python scripts/record_lio.py --case 2 --output output/new_lio_run.bag
../../integrations/fast_lio/build.sh
mkdir -p ../../integrations/fast_lio/data
cp output/new_lio_run.bag ../../integrations/fast_lio/data/input.bag
../../integrations/fast_lio/run.sh ../../integrations/fast_lio/data
```

导出程序拒绝覆盖已有 数据包。回放程序也拒绝覆盖输出。

已生成 `output/lio_pid_dwa_final.bag`：485 帧点云、9,682 条 IMU，包含静止初始化、平地、转弯和 0.7 m 高地。此数据由当时的 PID+DWA 导航产生，估计器尚未消费这些数据。

运行环境阻碍：Docker 存储位于系统根分区，剩余约 0.8 GB，不足以构建。构建脚本要求 12 GiB 余量。任务新下载的基础镜像已保存到工作区并从 Docker 存储移除。未删除原有数据，未修改 Docker 配置。详细版本、日志和后续命令在 `../../integrations/fast_lio/README.md`。
