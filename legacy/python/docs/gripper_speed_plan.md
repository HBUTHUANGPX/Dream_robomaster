# 16 倍执行速度实验

> **历史记录，不用于当前启动。** 首次使用请阅读[根目录说明](../../../README.md)和[入门说明](../../../docs/getting-started.md)。
> 本文的“当前”“已完成”和验收数据均指记录时的 Python 版本。命令以仓库内的 `legacy/python` 为工作目录。先按[归档环境说明](../README.md)准备依赖。`output/` 中的记录是本机历史产物，不保证随仓库提供。

为执行器和命令行增加显式运动速度倍率。播放速度独立设置。初始实验保留原执行器力矩上限、摩擦模型、接触确认和碰撞检查。

将腕部和夹爪的参考运动时长除以 16。测量实际轨迹和饱和情况，不能把更快的参考指令视为已经实现的物理运动。分别测试张开、腕部旋转和完整执行。

跟踪或接触检查失败时，立即停止执行并记录原因。不能通过渲染或改写状态隐藏失败。尝试过程使用实时播放速度。若硬件力矩上限阻止完成请求，应明确记录该限制。

## 现有执行器的验证结果

`DualGripperCube(speed=16)` 或 `--speed 16` 将物理运动参考设置为 16 倍。在 1 ms 积分步长下，腕部 90° 轨迹用时 53 ms，180° 轨迹用时 75 ms，夹爪轨迹用时 19 ms。这不表示夹爪在物理上跟上了参考轨迹。

力矩上限、增益、质量、摩擦、150 ms 稳定等待和接触确认均保持不变。视频可独立设置 `--playback 1`。

单次 90° 腕部旋转的峰值速度为 55.90 rad/s，约为 3203°/s，接近原速度的 16 倍。但在 19 ms 参考轨迹结束后，夹爪仍远未达到安全张开间隙。

完整的 20 步打乱与求解实验在 2、4、8、16 倍请求下均失败。2、4、8 倍因层对齐漂移失败，16 倍因张开间隙不足失败。

录制的 16 倍尝试包含 1 s 预录制等待，并在首次层对齐检查时停止。残差约为 1.30°，高于 1.15° 容差。这说明高速执行对稳定时间敏感，不能称为可复现的成功求解。

本机历史产物 `output/motion_speed_benchmark.json` 保存实际运动样本和失败记录。`output/dual_gripper_speed16/failure.json` 保存实时视频的停止原因。该视频记录失败尝试，不是完成的求解。

不得提高容差或关闭间隙检查来宣称成功。原始 1 倍执行仍是默认配置，早期成功的摩擦抓握视频保持不变。

临时参数探查提高了手指伺服刚度和可用力矩，但未证明 16 倍运动可靠。因此，该调整没有应用到实现。更高能力的执行器、机构和重新调参的控制器仍需进一步验证。
