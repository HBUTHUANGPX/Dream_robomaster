# 双夹爪魔方还原：固定安装、原地回位

> **历史记录，不用于当前启动。** 首次使用请阅读[根目录说明](../../../README.md)和[入门说明](../../../docs/getting-started.md)。
> 本文的“当前”“已完成”和验收数据均指记录时的 Python 版本。命令以仓库内的 `legacy/python` 为工作目录。先按[归档环境说明](../README.md)准备依赖。`output/` 中的记录是本机历史产物，不保证随仓库提供。

两个 MuJoCo Menagerie Robotiq 2F-85 分别位于魔方 +X、-Y 侧，夹爪对称中心的局部旋转轴穿过魔方中心，互成90°。安装位置固定，模型没有平移关节，也没有进退命令。这里的 `yaw` 指夹爪自己的旋转轴，而非世界竖直轴。

## 当前高速配置：腕部8倍、夹爪32倍

已新增独立的 `--wrist-speed 8 --jaw-speed 32` 配置，使用改装的高速平行夹爪模型和接触后限力控制。视频用 `--playback 1`，实际执行与播放倍率分开。高速配置改变了电机等效惯量、驱动增益/限幅及夹爪内部导向，不能视为原装 Robotiq 的性能规格。夹持仍完全通过接触摩擦。

```bash
MUJOCO_GL=egl uv run --group cube python record_dual_gripper_cube.py \
  --wrist-speed 8 --jaw-speed 32 --playback 1 \
  --output output/dual_gripper_wrist8_jaw32
```

详见 [高速配置与参数](gripper_split_speed_plan.md)。下文未特别标明的1ms步长、原始开合增益等描述属于早先的基础配置。高速配置使用0.1ms步长及独立闭环开合控制。

## 魔方关节与夹持模型

魔方采用混合约束模型：6 个中心块铰链、20个自由块以及可切换焊接约束。换层时根据当前块位置更新该层的连接关系，因此经过不同方向的连续转动后仍能继续打乱和还原。核心具有自由关节，机器人执行时由夹爪支撑，六个内部面电机关闭。没有通过逐帧覆盖 块体 `qpos` 实现动画。

每个夹爪保留上游四连杆开合机构，并增加一个腕部铰链。窄指尖只接触一个外层。为满足原地旋转净空，定制延长指尖相对之前版本向外偏移4mm/侧。上游 XML 和网格文件不变。开合控制值为0（打开）和115（夹持），使用上游0–255标度，不能直接理解为真实硬件力值。

夹爪开合和腕部旋转均通过 MuJoCo 执行器施力，夹爪与魔方之间完全依靠接触法向力和摩擦传递力/扭矩，模型中没有抓取焊接约束或连接约束。夹持建立前，两侧指尖必须持续40ms检测到正法向接触力。抓握与释放 只记录控制器状态，不添加连接。

基础配置定制指尖使用滑动摩擦系数1.2、扭转摩擦参数0.005m、`condim=4`、`priority=2`、`solref=0.002/1`、`solimp=0.9999/0.9999/0.001`，使指尖的接触设置明确生效，并减少连续交接中的软接触滑移。没有增加原夹爪执行器力上限。该参数是仿真设定，尚未经真实材料标定。内部块间碰撞仍关闭，内部焊接/锁层约束继续近似魔方机构。这与已删除的外部抓取约束不同。

## 求解与动作转换

`cube_solver.py` 从当前块的物理姿态读取54个 URFDLB 面片，把实际状态交给 `muodov/kociemba` 1.2.1，并独立重放验证解法。不是倒放打乱历史。

`gripper_plan.py` 维护整数3×3魔方到世界旋转矩阵。所有转面由A执行。使用固定规则将目标面朝向 +X，暂不搜索全局最短路径：

| 目标面的当前世界法向 | 整体旋转 |
| --- | --- |
| +X | 无 |
| -X | B +180° |
| +Z | B -90° |
| -Z | B +90° |
| +Y | A +90°，B -90° |
| -Y | A +90°，B +90° |

整体旋转时，持物手夹住核心，另一手释放并张开至安全开度。持物手旋转整个锁定的魔方。随后另一手接住，原持物手张开、原地回零、重新夹住。

转面时B支撑核心，A夹住目标层，释放该层内部锁定，按解法旋转，再锁定。A释放并打开至安全开度，原地回零。顺时针面动作对应A -90°，逆时针 +90°，半转 -180°。

### 原地旋转净空

约60mm魔方转动后的对角包络约85.14mm。程序要求测得的指尖内侧开口至少为：

```text
sqrt(2) * (3 * PITCH + 0.0002) + 0.004 = 0.089135656 m
```

即89.136mm，包含4mm总余量。发送打开命令后等待实际开度达标，不能只靠固定延时。该定制指尖完全打开时约93.2mm。

每个腕部旋转动作及其稳定阶段，每1ms检查一次实际开度与 MuJoCo 接触：打开手与魔方、两夹爪之间均不允许出现负接触距离，否则中止。正常闭合夹持接触允许存在。这是离散物理步的检测，不是连续时间或真实硬件的碰撞证明。

### 独立的后处理优化

先生成完整、保守的原始序列，再调用 `optimize_plan`：

- 删除紧邻的“闭合→夹住→释放→打开”，允许跨越状态检查点，检查点本身保留。
- 删除没有必要的短暂抓取/释放和重复开合命令。
- 每个候选改写均重放验证支撑关系、魔方动作、整体朝向及最终手部状态。

不修改任何实际腕部旋转的顺序、目标或模式，不做全局路线优化。优化器不修改输入，且重复优化结果不变。原始宏在边界保持双手夹住。优化后的边界可以只由一手支撑，最终状态仍为双手夹住、腕部回零。

## 文件与动作接口

| 文件 | 作用 |
| --- | --- |
| `cube_solver.py` | 物理姿态读取、面片转换和求解 |
| `gripper_plan.py` | 原始动作转换、独立优化、符号重放验证 |
| `dual_gripper_model.py` | 固定夹爪、腕关节、定制指尖与魔方场景 |
| `dual_gripper_cube.py` | 接触确认、开度反馈、碰撞检查和执行器 |
| `record_dual_gripper_cube.py` | 录像与 JSON/CSV 导出 |

`plan_unoptimized.json` 保存完整原始动作，`plan.json` 和 `steps.csv` 保存优化后的执行序列，`optimization.json` 保存优化统计。`scene.xml` 为生成模型（网格使用本机绝对路径，移动目录后应重新生成）。

动作类型包括 `jaw`、`yaw`（整块、单层、空转）、`grasp`、`release`、`layer_unlock`、`layer_lock`、`checkpoint`，没有 `slide`。`yaw` 单位为弧度。`jaw` 使用0–255控制标度。执行起始条件是双手夹住核心、腕角为零、临时装载夹具已关闭，由 `initialize_grasps()` 建立。

抓取事件是接触确认后的控制器状态转换，内部锁层事件属于魔方机构近似，不能把这些行直接当作真实机器人电机指令。真实执行还需要对应的接触/力反馈和层对齐检测。

## 摩擦版本验证（2026-10-08）

默认录像使用20步打乱和实际面片状态求解，原始510个动作，经独立后处理得到434个动作。`plan.json`、`plan_unoptimized.json` 和 `steps.csv` 保存序列，`verification.json` 保存本次实际结果，`grasp_checks.json` 保存接触记录。此前 `output/dual_gripper_inplace/` 是使用抓取 焊接约束 的历史版本，不代表当前纯摩擦执行。

本次录像已完成还原，视频46.4秒（4倍速），106,400个旋转物理步中禁止碰撞数为0，最小打开开口91.209mm。内部面电机力为0，数值警告为0。相对核心的最大还原位置误差0.00141mm、姿态误差0.274°。核心相对安装中心有约0.46mm自然夹持偏移，未通过抓取约束纠正。

专项测试检查不存在任何夹爪—魔方连接约束，并验证：单手侧向夹持时，正常摩擦可以保持高度。将摩擦清零后，魔方在重力下显著下滑。另外保留腕部力矩关闭后转面不能完成的反向测试。方形指尖可以通过法向力产生部分转矩，因此不能用“零摩擦时是否仍能转面”单独判断摩擦夹持真实性。

最终整体朝向可以不同于开始朝向，六面颜色应均还原。仿真中的纯摩擦成功不等于已标定真实夹爪或真实魔方的可靠性。

运动参考倍率使用 `--speed`，录像播放倍率使用 `--playback`，两者独立。例如：

```bash
MUJOCO_GL=egl uv run --group cube python record_dual_gripper_cube.py \
  --speed 16 --playback 1 --output output/dual_gripper_speed16
```

**16倍目前是未通过完整还原的实验配置。** 现有腕部可以达到接近16倍的单次转速，但夹爪未能在19ms内达到要求开度，完整执行也会出现转面对齐或旋转净空检查失败。程序保留检查并中止，导出 `failure.json` 和标明停止状态的录像。没有放宽阈值、添加抓取约束或暗中提高执行器力限。默认运动倍率仍为1。详细记录见 `docs/gripper_speed_plan.md`。
