# 图像自瞄一对一实施计划

> **历史记录，不用于当前启动。** 首次使用请阅读[根目录说明](../../../../../README.md)和[入门说明](../../../../../docs/getting-started.md)。
> 本文的“当前”“已完成”和验收数据均指记录时的 Python 版本。命令以仓库内的 `legacy/python` 为工作目录。先按[归档环境说明](../../../README.md)准备依赖。`output/` 中的记录是本机历史产物，不保证随仓库提供。

用户选定渲染图像视觉路线后，要求立即实现。本计划记录按 `superpowers:executing-plans` 流程执行的过程。

**目标：**实现可交互、由真实 RGB 检测驱动的一对一自瞄仿真。

**架构：**独立 `duel` 模块复用物理底盘。视觉与滤波不访问敌方真值。仿真、裁判和网页分别实现。

**技术：**MuJoCo、NumPy、SciPy、无窗口 OpenCV、Python 标准库 HTTP 和 Canvas。

**设计文档：**[对战设计](../../duel-design.md)。

## 全局约束

保留原有导航、魔方和底盘入口。新增 OpenCV，用于轮廓处理和 PnP。采用 SI 单位，X 向前、Y 向左、Z 向上。比赛参考 2026 V2.2.0。明确说明理想自身里程计和无空气阻力近似。

## 审查重点

- 无装甲、颜色不匹配或目标出画时，清除检测，并在失联后停火。
- 使用扫掠检测、最近碰撞和法向速度阈值，处理高速弹丸穿透及背面打击。
- 暂停时停止推进。重置时清空弹丸、滤波、热量和计分。
- 拒绝非数值、无效类型和越界命令。失焦后自动刹停。
- 渲染线程异常时向界面报告，不能继续显示旧的正常状态。

## 决策与结果

当时目录没有 `.git`。实施直接在用户工作区新增独立模块，没有初始化仓库或创建虚假提交。用户已授权实施，因此没有重复要求审批计划。

视觉输出相机坐标系的 `tvec` 和角点。跟踪接收 `tvec` 与自身相机位姿。任务接收滤波预测。服务调用 `task.state` 和 `task.command`。

任务一至三完成。测试先因缺少功能失败，再通过。新增检查覆盖真实 RGB PnP、失观停火、闭环命中和物理侧移。

早期验证发现，过宽的自碰撞使侧移受阻。修复使用独立接触位，保留机器人内部滚子碰撞排除。最终记录在修复后生成。

审查还修复了标量载荷注入、按入队时间计算驾驶有效期、云台吸收弹丸和跟随视角，并补充测试或界面改动。

任务四的验证保存在本机历史产物 `output/duel/validation.json`，全量结果保存在 `regression.log`。当时没有可用的浏览器自动化实例，因此仅验证 HTTP 和静态 JavaScript，并记录未完成人工界面验收的限制。
