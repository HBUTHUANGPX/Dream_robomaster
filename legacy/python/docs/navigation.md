# RMUC 2023 地形点选导航

> **历史记录，不用于当前启动。** 首次使用请阅读[根目录说明](../../../README.md)和[入门说明](../../../docs/getting-started.md)。
> 本文的“当前”“已完成”和验收数据均指记录时的 Python 版本。命令以仓库内的 `legacy/python` 为工作目录。先按[归档环境说明](../README.md)准备依赖。`output/` 中的记录是本机历史产物，不保证随仓库提供。

## 使用

在 `legacy/python` 目录运行：

```bash
uv sync --locked
uv run python -m navigation.server
```

浏览器打开 **http://127.0.0.1:8765**。服务只监听本机。

1. 在俯视图的绿色区域点选，或按预设目标按钮。浅色区域是高地，坐标及地面高度显示在鼠标提示中。
2. 青色线是全局路径，橙色线是局部预测轨迹，白线是估计行驶轨迹，淡绿色点是当前激光观测。
3. 右侧提供三维跟随画面、速度、配准残差、累计测量地图点数和任务状态。
4. 暂停会冻结仿真。继续后恢复。重置清除在线点图并返回初始位置。新目标替换旧目标。非法目标会明确拒绝。
5. 到达条件为距目标栅格中心约 0.13 m 内，且地面高度差不超过 0.12 m。地图栅格为 0.10 m，点击坐标吸附到栅格中心。

网页的定位真值误差仅用于仿真诊断。导航使用点云配准估计的位置，不从真值位置生成控制指令。三维相机也跟随估计位置。

## 使用的原地图

来源：[HBUTHUANGPX/Hbut_LC_sentry](https://github.com/HBUTHUANGPX/Hbut_LC_sentry)，提交 `c9a0b28e2f76ff7a8ac07ed4fb5f3ad1c776d068`。作者将 SolidWorks 地图导出为 `RMUS_map_ws/src/rmus_map_2/meshes/base_link.stl`。其 `README` 署名机械组陈思强、侯宇飞，并注明未建前哨站及非必要装饰。

- 原 STL：`assets/arena/rmuc2023.stl`，约 **15.02 × 27.84 m**，最高约 2.469 m，2976 个三角形。
- `assets/arena/source.json` 保存原路径、提交号、SHA256。同目录保留仓库 Apache-2.0 许可证。
- 视觉和激光都使用原 STL。MuJoCo 的普通碰撞网格会按凸包处理，直接用整个场地会把凹地形填平。因此碰撞将每个原始三角形向实体侧挤出 3 mm 成为独立凸薄棱柱。原接触面没有改平，没有额外添加坡道，也没有把地形换成凭空设计的简图。

## 雷达安装建议

采用 **两颗固定 MID-360**，不用运动云台。水平 360° 已覆盖四周，偏航扫描价值有限。俯仰运动会使外参随时间变化，增加编码器同步、点云去畸变和外参标定负担。固定正装+倒装可持续兼顾定位与近地形观测。

官方依据：[MID-360 技术参数](https://www.livoxtech.com/cn/mid-360/specs)、[官方下载页](https://www.livoxtech.com/cn/mid-360/downloads)、《用户手册》v1.2（2024.04）。PDF 原件与地址保存在 `assets/official/`。

| 项目 | 官方参数或本设计 |
| --- | --- |
| MID-360 视场 | 水平 360°，垂直 -7°～52° |
| 量程 | 40 m @10% 反射率。70 m @80% 反射率 |
| 近距 | 0.1 m 盲区。0.1～0.2 m 仅参考，本仿真丢弃小于 0.2 m 的返回 |
| 输出 | 200,000 点/s、典型 10 Hz。内置 IMU，手册说明 200 Hz 推送 |
| 外形与质量 | 65 × 65 × 60 mm，265 g/颗 |
| 电气 | 9～27 V DC，平均 6.5 W/颗。两颗应做统一时间同步，实际供电需覆盖启动/低温需求 |
| 上雷达 | 底盘轴心坐标 `(0, 0, 0.53)` m，正装。水平地面扫描原点约 0.614 m（含仿真光学偏移） |
| 下雷达 | 底盘轴心坐标 `(-0.11, 0, 0.44)` m，绕 X 轴翻转 180°，从上方悬挂。扫描原点约 0.508 m |
| 倒装安装面 | 水平地面约 0.580 m，满足手册倒装安装面不低于 0.5 m 的要求 |
| 支架 | 独立金属立柱、悬臂及 100 × 100 × 6 mm 简化安装板。正装立柱在壳体下，倒装支撑在壳体上方 |

官方手册安装章节允许任意朝向，但要求倒装安装面距地不小于 0.5 m、四周散热避空建议不小于 10 mm、金属安装板厚度不小于 3 mm且散热面积不小于 10000 mm²。实物应按官方 M3 孔位制作并复核连接器及线缆弯曲空间。

上雷达向下仅 7°，在约 0.614 m 高度时水平地面的理论近侧交点约为 **5.0 m**。倒装雷达下视可至 52°，对应约 **0.40 m**。这是理想几何交点，实际还受装甲、立柱、反射率和坡面遮挡影响，并非零盲区。高低错层也避免两颗雷达的窗口直接处于对方主视场内。实装仍需复核互射和遮挡。

导航版整体约 0.61 m 高，未按 600 mm 竞赛收纳包络制作折叠机构。当前用途是导航仿真原型。原始 `assets/robot.xml` 保持不变。

## 感知、规划和控制

### 输入与定位

`navigation/sensors.py` 将世界中的射线返回转换成带安装外参的机体系点云，再由模拟姿态观测去除 横滚和俯仰。每颗每帧发出 1600 条射线、10 Hz，即官方标称点率的约 8%。覆盖使用二维非重复准均匀序列，不复刻 Livox 专有扫描图案。范围截断到 40 m，测距加入 8 mm 标准差的理想化噪声。未模拟反射率相关检出概率、逐点扫描时间和运动畸变。

先做真实射线相交，再去除机器人自身返回，因此支架遮挡不会被当作透明。外壳为按官方尺寸建立的简化几何，未使用厂商内部光学模型。

定位器 `navigation/slam.py` 只接收点云、轮编码器里程计和陀螺积分。没有 MuJoCo 对象或真值接口。ICP 在重力对齐下估计 x、y、z、偏航，默认 CAD 模式使用网格法向执行点到平面配准、稳健权重和可观测性检查。无先验模式使用修剪的点到点配准。两者均限制修正幅度。配准失败退回里程计，连续失败触发停车。在线地图只累计传感器实际返回点，最多 40000 点，不把 CAD 点云冒充已扫描地图。

提供两种定位模式：默认 `--localization prior` 使用 CAD 表面采样和法向作为局部定位先验（需要已知初始位姿）。`--localization slam` 不向估计器提供任何 CAD 点云，启动时建立首帧地图，后续通过扫描到累计地图配准，同时定位和建图。两种模式的全局规划都使用已知赛场地形。

```bash
uv run python -m navigation.server --localization slam --port 8766
```

这是轻量重力对齐点云 SLAM/导航原型，不是完整未知环境自主探索系统。目前没有完整回环优化、未知区域探索、FAST-LIO/FAST-LIVO 或 ROS2 实车驱动。模拟 AHRS 姿态理想化，未实现真实 IMU 姿态融合。真实部署需要加入 Livox ROS Driver2、时间同步、去畸变、实测标定和成熟 LIO。

### 全局路径

从原网格向上表面构建 0.10 m 高度栅格，结合上方表面法向排除实体内部和不足 0.65 m 的净空。高度差超过约 28° 坡度界限的边界被屏蔽，并对不连续边界膨胀 0.38 m，给 570 mm 底盘保留余量。小型起伏按实际高度参加邻域坡度检查。不会因为局部小斜面的法向过陡而把整片中央起伏区判为断路。

A* 代价综合距离、高差和离障碍余量，禁止从对角障碍缝隙穿过。只有和起点连通的区域显示为可点选。原地图的孤立停机坪/高台没有可供该底盘驶入的通路，不能通过点击使其变为可达。

**当前栅格是 2.5D 顶层表示**：同一 XY 下若存在多个可行层，界面选择最高支撑面。原模型检测到多层单元，但没有实现隧道层/桥面层的分别点选。这限制了重叠层场景的完整可达性，不能宣称覆盖所有三维可达位置。

### 局部与底盘

控制频率为 10 Hz。DWA 同时搜索纵向速度、横向速度和偏航速度。平移方向不依赖车头朝向。前进、后退、侧移和移动中旋转均可用。默认不为目标朝向原地调头。接近坡道或检测到持续打滑时，允许行进中调整方向，以改善四轮牵引分配。

平地指令速度上限为 1.2 m/s，坡道为 0.55 m/s。恒速预测为 1 s，另检查完整制动段。线加速度为 1.6 m/s²。线制动减速度为 1.0 m/s²。角加减速度为 2.4 rad/s²。这些是规划模型参数，实际速度可能瞬时超调。障碍包络半径为 0.40 m。地形边界额外保留 3.5 cm 跟踪余量。

三路独立 PID 跟踪上一周期局部轨迹的参考位姿。纵向误差修正纵向速度。横向误差修正横向速度。偏航误差修正偏航速度。PID 输出再次检查动态窗口、功率、地形、障碍和制动距离。橙线显示实际指令对应的预测轨迹。

轮端功率模型区分纵向和侧向阻力，并计入加速、坡度、旋转和电机损耗。执行器每个物理步限制四轮力矩。默认估计电功率预算为 120 W。该模型未做实车标定，也不代表比赛官方功率限值。

前视点与临时绕行目标均通过地形和点云检查。没有动态全局重规划或障碍速度预测。复杂堵塞仍可能停车。超过 15 s 没有位置进展时退出目标。定位连续失败也触发停车。

代码：`navigation/dwa.py`、`navigation/control.py`、`navigation/power.py`、`navigation/task.py`。参数、功率公式和验收结果见 `docs/controller-optimization.md`。

执行器仅驱动原有四个轮轴。48 个被动滚子与原地图发生接触，底盘自由六自由度。导航版轮轴速度增益提高到 4，扭矩上限 10 N·m，摩擦系数 1.3，均为待实车标定参数。没有直接修改导航过程中的底盘位姿，没有重力补偿平移或瞬移到高地。

## 验证与文件

```bash
uv run --group dev python -m pytest -q tests/test_navigation.py tests/test_navigation_slam.py tests/test_simulation.py
uv run python scripts/validate_navigation.py --cases 0 1 2 3 4 5 6
```

- `output/navigation_validation.json`：逐目标实测、最大定位误差、真值轨迹及警告统计。
- `output/navigation_ramp_validation.json`：坡道目标实测。
- `output/navigation_ui.png`：实际浏览器渲染。
- `assets/navigation.xml`：独立完整场景。运行前需要同目录下对应的机器人网格和场地图。
- `scripts/build_navigation.py`：从原机器人及原 STL 重建导航场景。
- `navigation/terrain.py`：`uv run python -m navigation.terrain` 重建地形缓存。

验证过的具体终点不等于逐一验证所有绿格。全图自动检查验证拓扑可规划性。实际动力学仍受坡口、姿态、摩擦、初始条件和感知误差影响。不可将该原型当作“任何三维可达点必达”的实车保证。
