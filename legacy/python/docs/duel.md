## 启动

```bash
uv sync --locked --group dev
MUJOCO_GL=egl uv run python -m duel.server --port 8766
```

打开 http://127.0.0.1:8766/ 。与原导航的 8765 端口分开。仅监听本机。远程桌面可以通过 SSH 本地端口转发访问。关闭服务用 Ctrl+C。

默认静止对手、自瞄开启、双方自动开火关闭、双方无敌计分开启。移速范围0–4 m/s、转速0–4 rad/s，两者默认2。横移/原地旋转分别使用对应参数，绕圈同时使用两者。开启「对准后自动开火」即可观察完整闭环。再切换「往返横移」「绕圈」「原地旋转」。开启「敌方视觉自瞄反击」后，红方使用自己的渲染相机检测蓝色灯条。

- 按住 WASD 平移、QE 转向，松开停止。网页失焦停止发指令，服务端 350 ms 看门狗刹停。
- 空格或「单发」手动射击。手动单发不要求视觉锁定。空格不会误触上次聚焦的操作按钮。Esc 键或「立即停车」停止驾驶。输入框和下拉框保留原生键盘操作，操作后点击画面即可重新使用驾驶快捷键。
- 关闭自瞄后，拖动相机画面或方向键控制云台。「云台回中」切为手动并归零。回中/重置会等正在发送的拖动指令结束，防止旧指令覆盖新操作。
- 「CV 标注」显示检测四角、重投影点、预测弹道瞄点。「原始图像」显示同一相机原图。
- 「图像观测输入」关闭可模拟全部检测丢失。180 ms 内允许短时预测，超时禁止自动射击。600 ms 后轨迹失效，重新获得数字观测需积累4次有效观测才能开火。
- 暂停冻结仿真时间。重置清空弹丸、滤波、热量、血量、日志和统计，保留当前设置。切换热量配置会重置回合。
- 开火前热量保护默认开启。关闭可实验超热锁枪和图传中断。

## 实现边界

`duel/vision.py` 只接收 RGB：颜色阈值提取红/蓝灯条，形状筛选和配对，IPPE 平面 PnP，重投影误差筛选。随后以灯条四角透视矫正数字，调用原始 `rm_auto_aim` ONNX 分类。拒绝低于80%的结果、`negative` 标签、空白及小装甲不支持的 `1` 和 `base` 标签。没有语义分割、敌方位置查询、真值投影角点或真值装甲编号。受控光照下运行，未模拟实车曝光及镜头畸变。

相机为 800×600、垂直视场 45° 无畸变针孔模型。PnP 特征是 **当前 MJCF 中灯条中心距 124 mm、长度 52 mm**，不是装甲外壳宽高，也不声称是另一套官方通用识别尺寸。AM02 网格由已有官方 STEP 转换。每帧 PnP 与该帧相机外参同步读取。

`duel/rotor_tracking.py` 使用整车旋转模型：九个主状态 `[xc,vx,yc,vy,z,vz,yaw,omega,r1]`，另将 `r2,dz` 纳入联合协方差，总计11维。这样相邻装甲的不同半径/高度不会被滤波器吸收到车体运动中。观测为 RGB PnP 装甲位置/法向偏航。角度环绕、四板关联、编号一致性、马氏门限、Joseph 协方差更新与 `DETECTING`、`TRACKING`、`TEMP_LOST`、`LOST` 状态机均已实现。旧六维 `duel/tracking.py` 只保留作测试基线，实际控制已切换。

PnP 两个平面解由重投影误差、已知安装倾角15°及轨迹一致性选择。再参考同济固定倾角法，搜索 ±80° 偏航 最小化RGB角点重投影误差。不读取目标真实朝向。法向采用向外约定，装甲位置为车心 **加** 半径乘法向，与上游状态符号约定不同。深度测量标准差取 `max(0.015,0.008*depth²)` m，反映远处约10像素灯条导致的深度噪声。模型噪声是本仿真基线参数，非实车标定结果。

自身底盘位姿使用 **理想里程计**（本车 MuJoCo 位姿），结合本车云台编码器和相机外参。编码器误差、时延和外参不确定性没有联合估计。控制器在弹丸飞行时刻预测四板位置，选择朝向枪口的装甲，补偿重力与枪口速度。相机20Hz，预测/控制/射击判断100Hz。云台限速3.6 rad/s，位置伺服结合`kv/kp` 速度前馈，装甲选择增加迟滞。自动射击依据预测装甲的横/纵尺寸窗口，替代固定0.65°门限。页面显示等待原因和秒数。短时失观允许180 ms预测，之后停止自动开火。

## 数字模型与页面观察

原样复用 [rm_auto_aim 的 mlp.onnx](https://github.com/chenjunnn/rm_auto_aim/tree/f244d0e296327d73171311ec50bf5f88856077b1/armor_detector/model)，314058 字节，MIT。OpenCV DNN 直接推理，不需 ROS2、onnxruntime 或在线下载。权重、label.txt、许可证和提交/SHA256位于 `assets/rm_auto_aim/`。模型输出为`1/2/3/4/5/outpost/guard/base/negative`。**当前仿真只放置3号步兵**，不是所有编号都已完成渲染验收。

数字素材来自作者 [rm_vision_simulator](https://github.com/chenjunnn/rm_vision_simulator/tree/e937f21d3ecc64c1a5a624ee82f8f28e1767e926/Assets/Materials)，Apache-2.0，原始3.png、许可证及来源在 `assets/armor_labels/`。两队各四块装甲均贴3，阵营由灯条颜色区分。贴图的正面V坐标已修正（此前上下翻转），背面UV落在黑色区域，八面逐像素方向测试防止肉眼误判。贴图是相机可见的110×110 mm薄网格，不改变碰撞裁判。贴图编号不传入检测器。

预处理沿用上游32×28透视图 → 20×28中心裁切 → 灰度Otsu → 归一化 → 概率归一化。页面数字裁切图直接展示真实网络输入，无有效观测时清空。显示编号/概率、车心、两组半径、转速、切板计数和状态。CV画面的小方框是四板未来位置，十字是估计车心，菱形是弹道瞄点。`LOST` 期间保留的几何数据显示为已失效。

弹丸直径 17 mm、名义质量 3.2 g。沿枪口 +X 射出，初速加上枪口世界速度，受 9.81 m/s² 重力。弹丸解析推进，单独做每 1 ms 的线段扫掠裁判，不是动态 MuJoCo 刚体。不施加弹丸反冲、空气阻力、摩擦轮加速、弹跳和碰撞冲量。轨迹为球心，碰撞用半径扩大的盒体、圆柱和椭球，盒角、圆柱端缘及椭球膨胀有保守近似。车体、轮子和云台的基本几何体吸收弹丸。只对装甲正面、法向相对速度大于 12 m/s 的接触计分，单块装甲最小伤害间隔 50 ms。场地边界/地面吸收弹丸。

一对一 使用简化 12×8 m 平地、可选无敌或200 HP，非完整官方赛场与等级体系。无需加载 2023 导航场地。全景和验证程序可读取真值，但这些信息不输入自瞄。关闭无敌后按200 HP判胜并冻结回合。无敌模式命中不扣血但保留统计，热量/射频规则仍有效。开启无敌会恢复双方200 HP并解除已结束状态。

## 官方依据与尺寸

- [2026 规则入口](https://bbs.robomaster.com/wiki/20204847/809871)：本地 `assets/official/rules_2026_v2.2.0.pdf`，官方 2026-08-07 V2.2.0。初速 25 m/s（§3.3），17 mm 装甲伤害 20、法向阈值 >12 m/s、50 ms 最小间隔（§5.1.1），热量（§5.1.3），一级性能（表5-15）。现有 `assets/official/sources.json` 记录原始 URL 与 SHA256。
- 热量每发 +10，与初速无关。每 100 ms 冷却一次。一级冷却优先：上限40、冷却12/s。爆发优先：上限170、冷却5/s。超上限锁枪/图传，到0解锁。永久锁定阈值 Q0+100，正文使用 >，流程图使用 ≥，本实现采用流程图 ≥ 的保守边界。正常保护调度不会进入该分支。
- [AM02 官方装甲资料](https://bbs.robomaster.com/wiki/20204847/811816)：复用 `assets/official/armor_am02.step`、`armor_am02_manual.pdf` 和米制 OBJ。沿用现有装甲倾角15°。
- 本地 `assets/official/spec_2026_v2.0.0.pdf` **文件名与内容版本不一致**，来源记录及实际内容为 V1.4.1（2026-04-21），引用时以内容为准。印刷页80 / PDF第81页、图3-31：17 mm 发射管安装段外径21±0.03 mm，最大长度97 mm，建议壁厚≥1 mm。仿真使用97 mm安装段、21 mm外径、1 mm壁厚的参数化近似，并没有下载完整枪管CAD或模拟光电检测孔。
- [官方竞赛机器人3D图纸入口](https://www.robomaster.com/zh-CN/products/components/detail/2711)：提供整套2020自组装机器人下载，首版未导入整套大型装配，云台/发射器其余部分为明确标注的简化件。
- [官方17 mm弹丸参数](https://www.robomaster.com/zh-CN/products/components/detail/2499)：17 mm、3.2±0.1 g。仿真用解析球体，不需要另造弹丸CAD。

## 验证

```bash
MUJOCO_GL=egl uv run --group dev python -m pytest tests/test_duel.py tests/test_duel_render.py tests/test_duel_api.py tests/test_armor_classifier.py tests/test_rotor_tracker.py -q
MUJOCO_GL=egl uv run python scripts/validate_duel.py --seconds 8
MUJOCO_GL=egl uv run --group dev --group cube --group lio python -m pytest tests -q
```

全量测试必须在导入 MuJoCo **之前**指定 `MUJOCO_GL=egl`。仅在某个测试模块中设置环境变量不足以覆盖更早的导入。

`output/duel/validation.json` 包含各场景时间、实际目标位姿、命中数、跟踪比例、装甲位置误差、车心平面误差、数字有效观测比例和 MuJoCo 警告。同目录保存原图、CV 标注、数字裁切区域和全景截图。统计来自默认距离约4 m、指定运动和爆发优先配置，每回合结束即停止，不能作为复杂背景或实车精度保证。
