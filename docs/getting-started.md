# 首次使用指南

## 适用范围

本指南用于首次启动当前 C++/Rust 版本。
不需要先学习 CMake、Cargo 或 Python。
准备脚本会检查依赖。缺少系统软件时，准备脚本会请求管理员权限。

“仓库根目录”指包含 `rm`、`README.md` 和 `assets/` 的目录。
“终端”指输入命令的窗口。
“本机”指你正在操作浏览器的电脑。
“运行主机”指实际运行仿真程序的 Linux 电脑。
这两台电脑可以是同一台电脑。

## 开始前需要的条件

| 条件 | 要求 | 检查或处理方式 |
| --- | --- | --- |
| 操作系统 | Ubuntu 22.04 | 在系统设置中查看版本；其他系统未验证 |
| 处理器 | x86_64，也称 amd64 | 运行 `uname -m`，结果应为 `x86_64` |
| 仓库文件 | 完整源码与 `assets/` 资产 | 向仓库提供者取得完整目录；不要只下载程序源码 |
| 写入权限 | 当前用户能写入仓库目录 | 将仓库放入用户自己的目录，例如主目录 |
| 管理员权限 | 仅在缺少系统软件时需要 | 准备脚本使用 `sudo`；没有权限时联系主机管理员 |
| 网络 | 首次下载依赖和构建时需要 | 运行主机须能访问 Ubuntu 软件源、GitHub、Rust 和 Node.js 下载服务 |
| 存储空间 | 仓库分区容纳 SDK 和构建结果；系统分区容纳新安装的系统软件 | 执行 `df -h . /`；仓库分区建议预留至少 8 GiB，这是容量建议而非实测最小值 |
| 渲染驱动 | 支持 OpenGL/EGL | 网页服务启动时会实际初始化渲染；失败时按[渲染排错步骤](troubleshooting.md#渲染失败)处理 |
| 浏览器 | 支持 JavaScript、画布和 JPEG | 已验证 Firefox；其他浏览器尚未做同等验收 |
| 图形桌面 | 仅底盘或魔方窗口需要 | 在运行主机的图形桌面中执行窗口命令 |
| 端口 | 默认使用 8765 和 8766 | 已占用时，按[端口排错步骤](troubleshooting.md#端口已被占用)处理 |

网页模式不需要物理机器人、雷达、摄像头或 ROS。
当前版本不使用历史 Python 虚拟环境。
macOS、Windows、ARM 主机和其他 Linux 版本不在自动准备流程的验证范围内。
如果本机不符合条件，请在符合条件的 Linux 主机上运行，再设置远程访问。

## 取得仓库并打开终端

1. 下载[源码压缩包](https://github.com/HBUTHUANGPX/Dream_robomaster/archive/refs/heads/main.zip)。
2. 将压缩包解压到有写入权限的目录。
3. 保留 `assets/` 中的模型、图片和网络权重。
4. 在该目录打开终端。
5. 确认目录中存在 `rm`、`README.md` 和 `assets/`。

仓库地址是 [HBUTHUANGPX/Dream_robomaster](https://github.com/HBUTHUANGPX/Dream_robomaster)。
如果当前终端可以执行 `git --version`，也可用以下命令取得源码并进入目录：

~~~bash
git clone https://github.com/HBUTHUANGPX/Dream_robomaster.git
cd Dream_robomaster
~~~

没有 Git 时，使用前面的压缩包步骤即可。
如果终端不在仓库目录，先输入 `cd `，再拖入仓库文件夹，最后按回车。
终端会使用文件夹的实际路径。路径包含空格时，保留终端生成的引号或转义字符。

如果压缩包未保留执行权限，先执行：

~~~bash
chmod +x rm
~~~

## 准备环境

在仓库根目录执行：

~~~bash
./rm setup
~~~

准备脚本检查系统工具，补齐缺少的依赖，然后构建程序。
如果终端请求密码，输入当前 Linux 用户的管理员密码。
输入密码时，终端通常不显示字符。
如果当前用户没有管理员权限，让管理员安装提示的软件包。

首次编译 OpenCV 可能需要数分钟，具体时间取决于主机性能和网络。
本地 SDK 与 `build/`、`target/` 构建结果位于仓库内的忽略目录。
系统软件包写入系统分区。已有 Cargo 会沿用原有的下载缓存位置。
已有合适工具时，脚本会复用这些工具。
缺少 Rust 时，脚本将工具链安装到 `.deps/cargo/` 和 `.deps/rustup/`。
入口自动选择这些工具。无需修改终端配置。
如果还需要测试工具，改用 `./rm setup --with-tests`。
缺少 Node.js 时，这个选项会将固定版本安装到 `.deps/node/`。
普通准备和网页运行不要求 Node.js。

只有命令以成功状态结束后，才执行下一步。
如果下载或构建失败，保留终端中的第一条错误信息。
按[故障处理说明](troubleshooting.md)修复后，再执行同一条准备命令。

## 启动并使用网页

1. 在仓库根目录执行 `./rm`。
2. 等待终端显示导航和对战地址。
3. 在同一台电脑的浏览器中打开需要的地址。
4. 在导航页面点击地图中的可通行位置，设置目标。
5. 在对战页面使用页面上的运动、瞄准和射击控件。
6. 使用结束后，按下面的停止步骤关闭服务。

默认导航地址是 `http://127.0.0.1:8765/`。
默认对战地址是 `http://127.0.0.1:8766/`。
`127.0.0.1` 只指浏览器所在的电脑。
如果程序运行在另一台主机上，直接打开这个地址不会访问那台主机。

两个网页服务都在前台运行。关闭启动终端会影响服务。
刷新网页不会重启仿真。重新启动程序会创建新的仿真状态。
默认启动只绑定回环地址，不直接向局域网提供服务。

## 停止网页服务

1. 在运行服务的主机上打开另一个终端。
2. 使用启动服务时的 Linux 用户账号。
3. 进入启动服务时使用的仓库目录。
4. 执行 `./rm stop`。
5. 等待终端显示“本仓库的网页服务已停止”。

该命令停止这份仓库的全部网页服务。
它覆盖 `./rm`、`./rm navigation` 和 `./rm duel` 启动的服务，也覆盖自定义端口。
启动器收到停止请求后，会结束并回收对应的仿真进程。
没有运行中的服务时，终端显示“当前用户在本仓库没有运行中的网页服务”。
这也是正常结果。重复执行停止命令不会报错。

停止命令使用已经构建的 Rust 启动器，不重新构建，不检查开发环境或资产。
魔方窗口和底盘窗口仍使用各自的关闭方式。
如果只需停止某个启动终端中的服务，在那个终端按 `Ctrl+C`。
如果停止命令报错，按[停止失败说明](troubleshooting.md#停止服务失败)处理。

## 远程访问

先在运行主机上完成准备和启动步骤。
确认远程终端已显示两个服务地址。
再选择下面一种访问方式。

### 已有端口转发工具

1. 在端口转发工具中添加远程端口 8765。
2. 添加远程端口 8766。
3. 打开工具为每个端口显示的本地地址。

转发工具可能分配不同的本地端口。
以工具当前显示的地址为准，不使用其他会话中记录的临时端口。

### 使用 SSH 转发

本机需要安装 SSH 客户端。运行主机需要提供可用的 SSH 登录账号。
先向主机管理员取得用户名、主机地址和登录方式。
在本机打开另一个终端。

将下面命令中的 `用户名` 和 `主机地址` 替换为真实值：

~~~bash
ssh -N -o ExitOnForwardFailure=yes -L 8765:127.0.0.1:8765 -L 8766:127.0.0.1:8766 用户名@主机地址
~~~

完成登录后，保持这个终端打开。
没有持续输出是转发命令的正常状态。
在本机打开前面的两个默认网页地址。
使用结束后，在转发终端按 `Ctrl+C`。
这会停止转发。要停止仿真，在运行主机的仓库目录执行 `./rm stop`。

如果本机端口已占用，将命令中第一个 `8765` 改成 `18765`。
将第一个 `8766` 改成 `18766`。
远程端口仍保持 8765 和 8766。
此时浏览器地址改为 `http://127.0.0.1:18765/` 和 `http://127.0.0.1:18766/`。

## 使用窗口和无窗口任务

在运行主机的图形桌面中，执行 `./rm cube` 打开魔方窗口。
执行 `./rm robot` 打开底盘窗口。
窗口按键见[魔方说明](modules/cube.md)和[导航说明](modules/navigation.md)。

只有远程终端、没有图形桌面时，使用网页或无窗口任务。
例如，在仓库根目录执行下面命令，打乱并求解一个魔方：

~~~bash
./rm cube --headless --scramble "R U F' L2" --solve
~~~

该命令执行结束后返回终端。
双夹爪执行和录像需要额外参数，见[魔方说明](modules/cube.md)。

双夹爪默认使用十二元动作搜索。首次可只规划，先检查预算内是否找到解：

~~~bash
./rm cube --headless --dual --scramble "R U" --plan-only \
  --search-ms 1000 --objective execution_time --terminal-policy stable \
  --search-memory-mb 64 --search-threads 3 --output output/cube-first-plan
~~~

该命令创建模型并打乱，但不执行还原。
成功时 `output/cube-first-plan/robot_plan.json` 的 `found` 为 `true`。
没有解时命令失败退出；检查该文件的 `stop_reason` 和同目录的 `failure.json`。
这不表示魔方无解，可能是搜索预算不足。
默认最多三个搜索线程，受 CPU 和图内存预算限制。需要减少 CPU 占用时，改用 `--search-threads 1`。
参数、执行步骤和成本配置见[双夹爪搜索指南](cube-primitive-search.md)。

RX 窄指尖与 55 mm 魔方已接入 `./rm cube --dual --rx-bundle PATH`。
默认不启用 RX，也不会自动查找资产包。
先按 [RX 准备条件](rx-narrow-tip.md#准备条件)取得并校验用户提供的原包，再按[完整还原入口](rx-narrow-tip.md#完整还原入口)运行。
该入口已完成两组20步打乱的完整物理仿真还原。推荐命令使用3000毫秒预算和三个搜索线程。
限时搜索再次运行时可能选择不同计划。
RX 当前采用腕部 3 秒、夹爪 2 秒的基准斜坡时长，每次另等待 0.15 秒。
首次接入可使用倍率1；提速使用已验证的 `--speed 4 --wrist-speed 16 --jaw-speed 32`，同一62动作计划用时20.695秒，详见[RX提速配置](rx-narrow-tip.md#已验证的提速配置)。
本次还调整了数值接触参数，不能把完整还原归因于指尖几何改善，也不能当作实物性能。
搜索结果仅为预算内已找到的最佳解，不保证全局最优，也不支持动作重叠。

## 接入逐行 JSON 协议

此步骤供需要从程序发送魔方请求的用户使用。
先完成前面的准备环境步骤，再在仓库根目录执行：

~~~bash
mkdir -p output
printf '%s\n' '{"command":"state","args":{}}' | ./rm cube --rpc 2> output/cube-rpc.log
~~~

终端应显示一行 JSON。响应的 `ok` 字段应为 `true`。
输入结束后，程序退出。这个示例不需要图形桌面。
构建提示和诊断保存在 `output/cube-rpc.log`，不会进入协议输出。
客户端应分别读取标准输出和标准错误，不使用 `2>&1` 合并两条输出流。
日志有内容不表示失败。若程序退出失败或响应的 `ok` 为 `false`，按[协议排错步骤](troubleshooting.md#协议客户端无法解析响应)处理。

## 更新代码后

1. 在运行主机的仓库目录执行 `./rm stop`。
2. 更新仓库文件。
3. 在仓库根目录再次执行 `./rm`。

入口会执行增量构建。
如果入口提示依赖缺失，执行 `./rm setup`，再重新启动。
如果只想检查依赖，执行 `./rm doctor`。
