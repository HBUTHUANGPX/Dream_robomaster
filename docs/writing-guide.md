# 中文技术文档写作规范

## 目的与标准适用范围

本仓库文档帮助读者完成明确的操作。
读者应能从文档知道需要什么、做什么、得到什么，以及失败后如何处理。

ASD-STE100 是面向英文技术文档的受控语言标准。
其规则包含语法、句子结构、风格和受控词汇。
本仓库把其中适合中文的简明表达原则用于中文文档。
中文文档不宣称通过英文词典或英文词数规则的合规认证。
标准来源见[ASD 官方说明](https://www.asd-ste100.org/about_STE.html)。

## 中文范围

所有维护说明使用中文，包括首页、模块说明、设计记录、历史说明和帮助文本。
标题、表头、图片说明及命令中的解释注释也使用中文。

以下内容保留原样，防止改变程序含义或来源记录：

- 命令、路径、程序标识、协议字段和按键名称。
- 产品名称、标准名称、版本号、网址和哈希值。
- 第三方许可证及版权声明的原文。
- 厂商发布的原始资料；中文使用说明单独编写。

下载的 SDK 和上游参考检出放在忽略的依赖缓存中。
编译所需的 Kociemba 第三方源码随仓库保留，其说明使用中文。
缓存中的上游材料不作为本仓库的操作文档。
不要把一段英文操作说明整体放入代码块来规避中文要求。

## 句子规则

1. 每句表达一个意思。
2. 每条操作指令只要求一个主要动作。
3. 使用主动语态，并明确动作的执行者。
4. 使用“执行”“打开”“输入”“停止”等具体动词。
5. 先写条件，再写条件下的动作。
6. 对同一对象始终使用同一术语。
7. 直接写出单位、范围、文件位置和完成标志。
8. 不用“正常情况下”“适当配置”“自行安装”等不完整指令。
9. 不省略操作对象来缩短句子。
10. 将操作步骤与背景解释分开。

长条件、多个配置项和多项对照使用表格。
一个编号步骤中有两个不同时发生的动作时，拆成两个步骤。

## 每项操作必须交代的内容

| 内容 | 需要回答的问题 |
| --- | --- |
| 目的 | 这项操作解决什么问题？ |
| 前置条件 | 哪个平台、版本、权限、网络、文件或服务必须可用？ |
| 工作位置 | 命令在哪台电脑、哪个目录、哪个终端执行？ |
| 输入 | 用户需要替换哪些占位值？值从哪里取得？ |
| 动作 | 用户执行哪条命令，或点击哪个控件？ |
| 结果 | 哪个输出表示成功？生成文件在哪里？ |
| 失败处理 | 哪种错误需要停止？下一步做什么？ |
| 结束方式 | 前台服务如何停止？是否还有其他终端需要关闭？ |

“没有隐含前提”不表示软件没有依赖。
它表示文档明确说明所有影响该步骤的条件。
可把共用条件放入同一指南，并在操作开始处链接到该指南。

## 术语表

| 术语 | 本仓库含义 |
| --- | --- |
| 仓库 | 当前统一保存源码、资产和文档的目录 |
| 仓库根目录 | 包含 `rm`、`README.md` 和 `assets/` 的目录 |
| 模块 | 导航、自瞄对战或魔方的一组功能 |
| 服务 | 持续运行并接收浏览器请求的程序 |
| 终端 | 输入命令和查看程序输出的窗口 |
| 运行主机 | 实际执行仿真的 Linux 电脑 |
| 本机 | 用户操作浏览器的电脑 |
| 无窗口 | 不创建桌面窗口；图像渲染仍可能需要 EGL |
| 双夹爪 | 两个通过接触与摩擦操纵魔方的夹爪 |
| 准备 | 检查和安装依赖，再构建程序 |
| 构建 | 将源代码编译为可执行程序 |
| 验收 | 运行指定操作并检查其实际结果 |
| 历史记录 | 对过去版本的说明，不作为当前默认启动流程 |

首次使用专用缩写时，写出中文作用。
例如：“迭代最近点算法（ICP）用于点云配准。”

## 示例

不完整的说明：

> 配好环境后启动服务，然后访问页面。

完整的说明：

> 在 Ubuntu 22.04 x86_64 主机上打开仓库根目录的终端。
> 执行 `./rm setup`。
> 命令成功结束后，执行 `./rm`。
> 等待终端显示两个服务地址。
> 在同一台电脑的浏览器中打开需要的地址。
> 使用结束后，在启动终端按 `Ctrl+C`。

## 发布前检查

- 检查所有标题、说明、表头和注释是否使用中文。
- 检查每条可复制命令是否对应当前代码。
- 检查示例端口和输出路径是否一致。
- 检查所有本地链接是否存在。
- 检查远程操作是否区分本机和运行主机。
- 检查当前结果、历史结果和未验证内容是否明确区分。
- 运行文档检查器，并人工检查无法自动判断的内容。
