# 故障处理

本页命令均在仓库根目录执行。
先执行 `./rm doctor`，查看缺少的条件。
按对应问题完成处理后，再执行原来的命令。

## 找不到命令或文件

| 现象 | 原因或检查项 | 处理步骤 |
| --- | --- | --- |
| 找不到 `./rm` | 当前终端不在仓库根目录 | 打开包含 `rm` 和 `assets/` 的目录，再打开终端 |
| 执行 `./rm` 时提示权限不足 | 下载方式未保留执行权限 | 执行 `chmod +x rm`，然后重试 |
| 缺少编译器、CMake、Rust 或 SDK | 环境准备未完成 | 执行 `./rm setup` |
| 缺少模型、贴图或分类器 | 仓库资产不完整 | 从同一仓库版本补齐提示的文件，再启动 |
| 提示平台不支持 | 系统或处理器不在验证范围 | 在 Ubuntu 22.04 x86_64 主机上运行 |
| 提示 Node.js 版本不满足 | 测试工具过旧 | 执行 `./rm setup --with-tests`；网页运行本身不依赖 Node.js |

模型与程序的关节名称、相机名称和坐标约定必须匹配。
补齐资产时，使用同一仓库版本的文件。

## 端口已被占用

默认导航端口是 8765。默认对战端口是 8766。
新启动的程序不会终止占用端口的已有程序。

如果已有服务就是你要使用的服务，直接打开已有网页。
如果需要重新启动本仓库的服务，执行 `./rm stop`。
等待停止命令成功结束后，再执行 `./rm`。
如果不能停止已有服务，选择两个空闲端口：

~~~bash
./rm start --navigation-port 18765 --duel-port 18766
~~~

使用终端显示的新地址。
远程访问时，同时修改端口转发的远程端口。
终止进程前，先确认该进程的用途。

## 停止服务失败

在运行服务的主机上，用启动服务时的 Linux 用户账号执行 `./rm stop`。
当前目录必须是启动服务时使用的同一份仓库。
命令只停止当前用户在这份仓库中运行的网页服务。
它不会按端口终止其他程序，也不会使用遗留的进程编号文件。

| 终端信息或现象 | 处理方式 |
| --- | --- |
| 没有运行中的网页服务 | 这是正常结果；如果网页仍能访问，检查主机、用户账号和仓库目录是否一致 |
| 找不到已构建的启动器 | 在原启动终端按 `Ctrl+C`；下次启动前执行 `./rm setup` |
| 已有启动器仍是旧版本 | 在原启动终端按 `Ctrl+C`，再执行 `./rm` 完成构建与启动 |
| 无法确认进程或无法停止进程 | 保留完整错误信息；在原启动终端按 `Ctrl+C` |
| 等待服务退出超时 | 命令已等待 10 秒；检查启动终端的错误信息，然后再次执行 `./rm stop` |

停止命令不会在超时后强制终止进程。
只有命令成功结束后，才重新启动服务。

## 网页无法打开

1. 检查启动终端是否仍在运行。
2. 检查终端是否已显示服务地址。
3. 如果浏览器与程序位于同一台电脑，打开终端显示的地址。
4. 如果程序位于远程主机，检查端口转发是否仍在运行。
5. 检查本地端口是否与转发工具当前显示的端口一致。

SSH 转发命令使用 `-N` 时，登录后通常没有输出。
这个终端必须保持打开。
关闭转发终端后，浏览器无法继续访问远程服务。

如果页面能打开，但操作返回来源校验错误，请使用完整的回环地址。
保持页面主机名和端口一致。
服务支持 `localhost` 和 `127.0.0.1` 的本地转发。

## 渲染失败

网页使用无窗口渲染，但仍需要 OpenGL/EGL 驱动。
只安装开发头文件不能证明渲染驱动可用。

1. 保留启动终端中的 EGL、OpenGL 或驱动错误信息。
2. 在具有可用驱动的 Linux 环境中重试。
3. 如果主机由他人管理，将错误信息交给管理员检查显卡驱动或软件渲染支持。
4. 驱动修复后，重新执行 `./rm`。

设置 `DISPLAY` 只能选择图形会话，不能修复驱动。

## 窗口无法打开

魔方窗口和底盘窗口需要运行主机的图形桌面。
普通 SSH 连接通常不提供这个条件。

在运行主机的桌面终端中执行窗口命令。
只有 SSH 终端时，使用网页模式或 `--headless` 无窗口模式。
可执行的无窗口魔方示例见[首次使用指南](getting-started.md#使用窗口和无窗口任务)。

## 协议客户端无法解析响应

魔方的逐行 JSON 入口是 `./rm cube --rpc`。
标准输出只包含协议响应。构建提示和诊断写入标准错误。

1. 确认客户端只把标准输出交给 JSON 解析器。
2. 移除命令中的 `2>&1`，以免构建日志与响应混合。
3. 按[协议示例](getting-started.md#接入逐行-json-协议)保存并检查标准错误日志。
4. 如果构建失败，按下面的构建失败说明处理，然后重试。

构建失败时，程序以失败状态结束，不启动魔方进程。
此时标准输出可以为空，不表示客户端漏收响应。
若收到 `ok` 为 `false` 的 JSON，检查其中的 `error` 字段和请求内容。

## 双夹爪搜索失败或结果不符预期

命令和参数格式见[十二元动作搜索指南](cube-primitive-search.md)。
命令行模式先查看本次输出目录中的 `robot_plan.json`，再检查 `failure.json`。
RPC 先检查 `ok` 和 `error`；`ok:true` 后还须检查规划结果的 `found`。

| 现象 | 检查与处理 |
| --- | --- |
| `found:false`，`stop_reason` 为 `deadline` | 搜索预算包含首解、表读取和候选优化；增加 `--search-ms` 后重试，例如从 1000 改为 5000 |
| 未还原状态使用 0 毫秒预算没有解 | 这是预期行为；设置正预算，不会强行调用旧求解器兜底 |
| `stop_reason` 为 `memory_limit` | 图搜索工作内存受限；主机资源允许时增大 `--search-memory-mb`，例如改为 128；它不是进程 RSS 上限 |
| 求解表缺失、长度错误或校验失败 | 从同一仓库版本恢复报错路径下的 `cprunetables` 文件，并确认读取权限；不会自动生成表，不要绕过校验 |
| 成本配置被拒绝 | CLI 传文件路径，RPC 传内联对象；检查动作名、模式名及 0 到 3600 秒的数值；JSON 小数须带前导零 |
| 搜索参数被拒绝 | CLI 须启用 `--dual` 且不使用 `--viewer`；检查目标、终态策略、预算范围和整数内存上限 |
| `overlap` 被拒绝 | 当前只支持串行动作；移除该字段，不把它设置为 `false` 来请求兼容 |
| 末腕角非零或只闭合一侧 | 默认 `stable` 允许此终态；需要两腕归零且双闭合时用 `--terminal-policy home`，整体朝向仍任意 |
| 改了成本但物理速度没变 | 成本只改变计划评价；控制速度由 `--wrist-speed` 和 `--jaw-speed` 设置 |
| `execute_primitives` 请求失败 | 使用 `gripper` 的 `action` 字段；先初始化夹持，传字符串数组，并核对当前状态与计划起态；不要绕过图约束 |
| 计划找到但物理执行失败 | 软件色块重放不等于 MuJoCo 验收；保留失败记录，RPC 用 `reset` 重建场景，CLI 重新启动后再规划 |

不要把上一次输出目录中的 `plan.json` 当成本次计划。
`found:false` 时可能只有新的 `robot_plan.json` 和 `failure.json`，没有新的 `plan.json`。
预算或内存耗尽后若 `found:true`，结果是已找到的最佳计划，不代表全局最优。
`--plan-only` 没有执行还原；总耗时还包含程序和模型启动，不能直接与 `estimated_execution_s` 比较。
新图的转换表在内存缓存，无需运行离线生成命令。
新搜索长场景尚在验收，旧版成功数据不能代替本次物理执行记录。

## 下载或构建失败

| 终端信息 | 处理方式 |
| --- | --- |
| 连接超时、域名解析失败 | 检查运行主机网络，然后重新执行 `./rm setup` |
| SHA-256 校验失败 | 检查下载来源和网络，然后重试；保留校验步骤 |
| `sudo` 权限不足 | 将脚本列出的软件包交给管理员安装 |
| 磁盘空间不足 | 执行 `df -h .`；确认是仓库分区还是系统分区不足 |
| 编译器因内存不足被系统终止 | 关闭其他占用内存的任务，或在资源足够的主机上构建 |
| 移动仓库后 CMake 报旧路径 | 保留旧构建缓存，然后重新构建 |

如果移动仓库后需要重建，并且 `build/` 已存在，先执行：

~~~bash
mkdir -p output
mv build "output/build-before-move-$(date +%Y%m%d-%H%M%S)"
./rm build
~~~

日志和录像可能占用较多空间。删除前，先确认不再需要保留。
保留 `assets/`、`legacy/` 和第三方许可证。

## 录像或可选集成失败

录像需要 FFmpeg。文件写入你指定的输出目录。
确认该目录可写，并保留足够存储空间。

CAD 转换需要额外的 OCCT 开发库，见[CAD 说明](modules/cad.md)。
FAST-LIO 需要 Docker 和独立的存储空间，见[集成说明](../integrations/fast_lio/README.md)。
普通网页和魔方启动不需要这些可选集成。

## 报告无法解决的问题

提供以下信息，便于维护者复现：

- 你执行的完整命令。
- `./rm doctor` 的输出。
- 终端中的第一条错误及后续上下文。
- 你是在本机使用，还是通过远程转发使用。
- 代码版本；如果没有提交编号，提供取得仓库的日期。

不要提供密码、访问令牌或 SSH 私钥。
