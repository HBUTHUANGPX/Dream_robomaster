# 故障处理

本页命令均在仓库根目录执行。
先执行 `./rm doctor`，查看缺少的条件。
按对应问题完成处理后，再执行原来的命令。

## 找不到命令或文件

| 现象 | 原因或检查项 | 处理步骤 |
| --- | --- | --- |
| 找不到 `./rm` | 当前终端不在仓库根目录 | 打开包含 `rm` 和 `assets/` 的目录，再打开终端 |
| 执行 `./rm` 时提示权限不足 | 下载方式未保留执行权限 | 执行 `chmod +x rm`，然后重试 |
| 缺少编译器、CMake、Rust 或 SDK | 环境准备未完成 | 执行 `./rm setup` |
| 缺少模型、贴图或分类器 | 仓库资产不完整 | 从同一仓库版本补齐提示的文件，再启动 |
| 提示平台不支持 | 系统或处理器不在验证范围 | 在 Ubuntu 22.04 x86_64 主机上运行 |
| 提示 Node.js 版本不满足 | 测试工具过旧 | 执行 `./rm setup --with-tests`；网页运行本身不依赖 Node.js |

模型与程序的关节名称、相机名称和坐标约定必须匹配。
补齐资产时，使用同一仓库版本的文件。

## 端口已被占用

默认导航端口是 8765。默认对战端口是 8766。
新启动的程序不会终止占用端口的已有程序。

如果已有服务就是你要使用的服务，直接打开已有网页。
如果需要重新启动本仓库的服务，执行 `./rm stop`。
等待停止命令成功结束后，再执行 `./rm`。
如果不能停止已有服务，选择两个空闲端口：

~~~bash
./rm start --navigation-port 18765 --duel-port 18766
~~~

使用终端显示的新地址。
远程访问时，同时修改端口转发的远程端口。
终止进程前，先确认该进程的用途。

## 停止服务失败

在运行服务的主机上，用启动服务时的 Linux 用户账号执行 `./rm stop`。
当前目录必须是启动服务时使用的同一份仓库。
命令只停止当前用户在这份仓库中运行的网页服务。
它不会按端口终止其他程序，也不会使用遗留的进程编号文件。

| 终端信息或现象 | 处理方式 |
| --- | --- |
| 没有运行中的网页服务 | 这是正常结果；如果网页仍能访问，检查主机、用户账号和仓库目录是否一致 |
| 找不到已构建的启动器 | 在原启动终端按 `Ctrl+C`；下次启动前执行 `./rm setup` |
| 已有启动器仍是旧版本 | 在原启动终端按 `Ctrl+C`，再执行 `./rm` 完成构建与启动 |
| 无法确认进程或无法停止进程 | 保留完整错误信息；在原启动终端按 `Ctrl+C` |
| 等待服务退出超时 | 命令已等待 10 秒；检查启动终端的错误信息，然后再次执行 `./rm stop` |

停止命令不会在超时后强制终止进程。
只有命令成功结束后，才重新启动服务。

## 网页无法打开

1. 检查启动终端是否仍在运行。
2. 检查终端是否已显示服务地址。
3. 如果浏览器与程序位于同一台电脑，打开终端显示的地址。
4. 如果程序位于远程主机，检查端口转发是否仍在运行。
5. 检查本地端口是否与转发工具当前显示的端口一致。

SSH 转发命令使用 `-N` 时，登录后通常没有输出。
这个终端必须保持打开。
关闭转发终端后，浏览器无法继续访问远程服务。

如果页面能打开，但操作返回来源校验错误，请使用完整的回环地址。
保持页面主机名和端口一致。
服务支持 `localhost` 和 `127.0.0.1` 的本地转发。

## 渲染失败

网页使用无窗口渲染，但仍需要 OpenGL/EGL 驱动。
只安装开发头文件不能证明渲染驱动可用。

1. 保留启动终端中的 EGL、OpenGL 或驱动错误信息。
2. 在具有可用驱动的 Linux 环境中重试。
3. 如果主机由他人管理，将错误信息交给管理员检查显卡驱动或软件渲染支持。
4. 驱动修复后，重新执行 `./rm`。

设置 `DISPLAY` 只能选择图形会话，不能修复驱动。

## 窗口无法打开

魔方窗口和底盘窗口需要运行主机的图形桌面。
普通 SSH 连接通常不提供这个条件。

在运行主机的桌面终端中执行窗口命令。
只有 SSH 终端时，使用网页模式或 `--headless` 无窗口模式。
可执行的无窗口魔方示例见[首次使用指南](getting-started.md#使用窗口和无窗口任务)。

## 下载或构建失败

| 终端信息 | 处理方式 |
| --- | --- |
| 连接超时、域名解析失败 | 检查运行主机网络，然后重新执行 `./rm setup` |
| SHA-256 校验失败 | 检查下载来源和网络，然后重试；保留校验步骤 |
| `sudo` 权限不足 | 将脚本列出的软件包交给管理员安装 |
| 磁盘空间不足 | 执行 `df -h .`；确认是仓库分区还是系统分区不足 |
| 编译器因内存不足被系统终止 | 关闭其他占用内存的任务，或在资源足够的主机上构建 |
| 移动仓库后 CMake 报旧路径 | 保留旧构建缓存，然后重新构建 |

如果移动仓库后需要重建，并且 `build/` 已存在，先执行：

~~~bash
mkdir -p output
mv build "output/build-before-move-$(date +%Y%m%d-%H%M%S)"
./rm build
~~~

日志和录像可能占用较多空间。删除前，先确认不再需要保留。
保留 `assets/`、`legacy/` 和第三方许可证。

## 录像或可选集成失败

录像需要 FFmpeg。文件写入你指定的输出目录。
确认该目录可写，并保留足够存储空间。

CAD 转换需要额外的 OCCT 开发库，见[CAD 说明](modules/cad.md)。
FAST-LIO 需要 Docker 和独立的存储空间，见[集成说明](../integrations/fast_lio/README.md)。
普通网页和魔方启动不需要这些可选集成。

## 报告无法解决的问题

提供以下信息，便于维护者复现：

- 你执行的完整命令。
- `./rm doctor` 的输出。
- 终端中的第一条错误及后续上下文。
- 你是在本机使用，还是通过远程转发使用。
- 代码版本；如果没有提交编号，提供取得仓库的日期。

不要提供密码、访问令牌或 SSH 私钥。
