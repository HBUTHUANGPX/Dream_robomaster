# 双夹爪搜索优化实验

历史记录：本页对应提交 `03c17cb` 的串行优化。当前入口和并行实测见[并行搜索实验](cube-parallel-search.md)。

## 本次范围

2026-10-09 在同一台机器上比较基线提交 `93227bb` 与当前搜索实现。
基线程序和静态库在修改前冻结；本页数字均来自本次重新运行，不是上游仓库的成绩。
参考 [rubiks-cube-arm-solver](https://github.com/Mario-Ancx/rubiks-cube-arm-solver/tree/ea81975af83ddb000bcd154f6c4cd0288e36b20b) 的准备动作复用和旋转共轭思路，未复制其源码。

目标是预计执行时间。搜索耗时不加到目标中，只受预算约束。
十二元动作、有符号腕角、碰撞限制、摩擦夹持和执行器参数保持原样。

## 验证方法

采用种子 `20261009` 产生十二个二十步打乱，再用种子 `20261010` 产生十二个复验打乱。
每轮额外包含五个已还原或短序列边界例；下表均只统计二十步打乱。
默认成本对应腕速八倍、夹爪速度三十二倍，终态为 `stable`。

每个返回方案均通过独立整数机械模型与贴纸重放，核对行程、支撑、朝向、最终还原和累计成本。
候选搜索不创建 MuJoCo 模型。物理仿真仅用于最后的抽样验收。
每轮从新进程开始，按相同顺序执行案例，进程内缓存保留。
原始记录保留边界例的冷启动耗时；表中随机样本在此前五个边界例之后执行，属于缓存已建立的比较。
这些数字不能视作每次新进程启动的耗时。
计时只覆盖搜索接口，不含输入生成、验证或输出文件。

## 固定面解的搜索开销

将第一批打乱的逆序作为固定面解，分别求机器人路径。预算为五百毫秒。
这项比较固定输入和最优成本，衡量候选评估本身的速度。

| 方案 | 平均搜索时间 | 平均完整状态展开数 | 平均最优执行成本 |
| --- | ---: | ---: | ---: |
| 原版 Dijkstra | 21.40 毫秒 | 85799 | 15.59969 秒 |
| 保留朝向和开合的 72 状态下界 | 13.11 毫秒 | 46865 | 15.59969 秒 |
| 额外保留腕奇偶的 216 状态下界 | 2.84 毫秒 | 775 | 15.59969 秒 |

选择 216 状态下界。它放宽腕限位，但保留左右腕身份、动作方向、开合及横腕限制。
完整状态图仍检查真实有符号腕角；简化状态不参与执行。
反向最短路生成剩余成本下界，随后 A* 搜索真实状态图。
下界拓扑在进程内复用；成本下界按当前配置重新计算，避免切换成本后使用旧表。

## 完整搜索的方案对照

第一批十二个打乱，每个搜索五百毫秒，所有方案均找到有效解。

| 方案 | 平均预计执行时间 | 结论 |
| --- | ---: | --- |
| 原版 | 15.09235 秒 | 对照 |
| 216 状态下界，单坐标系 | 14.75462 秒 | 保留加速方法 |
| 二十四坐标系轮流取少量首解 | 15.30012 秒 | 重复首解开销较大，未采用 |
| 单坐标系，每条候选枚举最多八种组合重排 | 14.87456 秒 | 挤占其他候选预算，未采用 |
| 216 状态下界，三个不同两阶段主轴 | 14.72419 秒 | 采用 |

另试验只在候选改善当前方案后追加四种组合重排。一秒预算下，第一批平均只改善约三毫秒，第二批没有改善。
收益不足以支持增加默认流程复杂度，因此未采用。原型保存在本机 `output/search-experiments/reorder-prototype/`。

当前从二十四种旋转共轭中选择三个不同两阶段主轴，恒等坐标系优先。
总预算按约六成、两成、两成分配。小于二百五十毫秒时只使用恒等坐标系。
同一完整候选去重；相邻对立面交换保留。枚举、候选优化和交换变体共用当前坐标系的分片期限，分片期限不超过总截止时间。
被分片打断的候选保留已有完整路径，并允许其他坐标系再次评估。
完整有符号腕图上的稠密宏动作动态规划只完成了设计评估，没有做性能实现，不宣称其速度更慢。

## 物理与回归验收

固定二十步打乱、腕速八倍、夹爪速度三十二倍、搜索预算三秒，成功还原。
方案为六十个元动作，预计执行 13.41875 秒，实际仿真执行 13.36810 秒。
内部面电机力为零，MuJoCo 警告为零。物理日志位于本机 `output/search-experiments/physical-full20/`。
该案例主要验证执行兼容性，相比上一版同一案例没有进一步缩短。

新增二十四种旋转的 768 组独立贴纸映射测试，以及非单位朝向、非对称成本和已知最优上界的交叉测试。
成本尺度覆盖极小正数、普通值和接近配置上限的值。

## 复现当前基准

在仓库根目录，先按[首次使用](getting-started.md#准备环境)完成 `./rm setup --with-tests`。
构建纯软件基准：

```bash
cmake --build build --target rm_cube_search_benchmark
```

运行第一批案例，将结果保存到未存在的输出路径：

```bash
mkdir -p output/search-benchmark
build/bin/rm_cube_search_benchmark --root "$PWD" \
  --count 12 --seed 20261009 --budget-ms 1000 \
  --output output/search-benchmark/seed20261009.jsonl
```

将种子改为 `20261010`，并换一个输出文件名，可运行第二批。
`--mode search` 只测完整搜索，`--mode optimize` 只测固定面解，默认两者都测。
`--prepare-only` 只输出确定性输入集。

成功时进程退出码为零，返回方案的 `verified_solved` 为 `true`。
`found:false` 表示预算内没有方案，统计时不能把其空成本当作零。
存在 `error` 字段或独立验证失败时，程序非零退出；停止性能比较，先处理错误。
输出文件已存在时程序拒绝覆盖，须选择新文件名。

本机原始记录和汇总位于 `output/search-experiments/`，包括冻结的基线程序、逐例 JSONL 和 `summary.json`。
生成数据不随源码提交；其他机器运行时应使用新输出目录并记录环境。
