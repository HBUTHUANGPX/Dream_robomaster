# 使用流程与中文文档改进计划

## 目标

用户需要较少的命令。文档必须说明全部操作条件。
仓库说明必须使用中文。英文仅用于程序标识、命令和来源专名。
中文写作采用 ASD-STE100 的简明表达原则。

## 实施范围

1. 增加根目录入口 `./rm`。
2. 增加环境检查和首次准备命令。
3. 让 Rust 在同一终端启动两个网页服务。
4. 明确启动失败、端口占用和退出时的行为。
5. 重写首页、首次使用、排错和开发说明。
6. 中文化模块、历史设计和第三方模型说明。
7. 将重复的 FAST-LIO 上游检出目录移至忽略的依赖缓存。
8. 保留原始许可证、官方资料和历史源代码校验值。
9. 检查文档语言、链接、命令与实际行为是否一致。

## 分工

| 执行者 | 修改范围 |
| --- | --- |
| 导航工作者 | 根脚本、环境准备、构建入口、入口测试 |
| 对战工作者 | Rust 双服务启动、中文帮助、进程生命周期测试 |
| 魔方工作者 | 模块、历史和模型来源文档 |
| 主工作者 | 首页、完整操作指南、文档规范、集成与最终验收 |

## 验收条件

- 首次使用只需准备命令和启动命令。
- 日常启动只需 `./rm`。
- 缺少条件时，入口说明缺少项和下一步操作。
- 端口冲突不影响已有服务。
- 退出时，新启动的两个服务均结束。
- 文档说明支持的平台、终端位置、网络、权限、显示和端口条件。
- 当前说明、历史说明和文档标题均为中文。
- 代码标识和法定许可原文保留原样。
- 不把历史测试结果写成本次验收结果。
- 统一测试通过后，记录结果与无法验证的边界。
