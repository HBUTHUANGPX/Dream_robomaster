# 双夹爪并行求解实施计划

用户已授权尝试并行，并以实测判断是否提高求解效率。本计划沿用纯软件校验、十二元动作和执行耗时目标。

## 设计

先分离表准备与候选枚举。每次请求按截止时间校验表文件，首次安全发布后只读共享；每个工作线程拥有独立求解上下文、A* 队列和路径标签。
三个不同两阶段主轴可并行探索。已找到的最好成本作为共享上界，完整方案在锁内替换，异常取消全部工作并等待线程退出。
单线程模式保留现有分片策略，以区分表复用和并行本身的收益。支持一至三个工作线程，受硬件并行度和请求图内存预算限制。
MuJoCo 与 EGL 对象仍只由创建线程使用。搜索线程只操作软件状态。

## 验收条件

工作目录为仓库根目录。环境由 `./rm setup --with-tests` 准备。
性能试验串行运行，避免不同基准相互争抢 CPU；原始记录写入 `output/parallel-search/`。
独立软件重放必须确认每个方案的机械合法性和最终还原。限时结果不保证不同线程调度下完全相同。
运行 `./rm test` 和 `node tools/check-docs.mjs`，预期全部通过。

## 本次结果

两批共二十四个随机打乱表明：一秒三线程平均候选吞吐约为新版单线程的 3.06 倍，平均首解从 42.41 毫秒降至 22.93 毫秒。
一百七十个基准结果全部通过独立软件重放；完整测试及消毒器检查通过，物理抽样成功还原。
审查发现的短分片候选漏评已修正。详细边界、原始文件位置和复现命令见[并行搜索实验](../../cube-parallel-search.md)。
