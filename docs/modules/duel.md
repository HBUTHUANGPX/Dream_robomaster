# 自瞄对战模块

技术名称和缩写见[术语表](../glossary.md)。

`rm_duel` 使用 C++ 实现双机器人 MuJoCo 场景、相机渲染、视觉、跟踪、云台控制、射击和伤害判定。运行过程不使用 Python，也不使用预先录制的敌方轨迹。Rust 服务按顺序向原生进程发送请求。

## 启动与检查

首次使用时，请先阅读[根目录说明](../../README.md)和[入门说明](../getting-started.md)。下列命令均在仓库根目录运行。先完成 `./rm setup`。

```bash
./rm duel
```

该命令在前台启动对战服务。在启动终端按 `Ctrl+C` 停止这次启动的服务。
也可以在运行主机的另一个终端中，进入同一仓库目录并执行 `./rm stop`。
停止命令会关闭当前用户在本仓库启动的全部网页服务。
可通过 `./rm duel --port 8766` 指定端口。需要同时启动导航与对战时，运行 `./rm` 或 `./rm start`。

以下原生命令供诊断和模块验证使用：

```bash
ctest --test-dir build -R '^duel_' --output-on-failure
build/bin/rm_duel --root "$PWD" --rpc
build/bin/rm_duel --root "$PWD" --headless --duration 8
```

`--ticks N` 推进 N 帧仿真并输出状态。`--headless --duration 秒数` 运行有时限的无窗口仿真。未知参数、格式错误和冲突的运行模式均会报错。

每次 `tick` 推进 50 ms 的物理仿真，并获取一次相机观测。瞄准和射击窗口每 10 ms 检查一次。模型保留 1 ms 的积分步长，以及通过接触驱动的麦克纳姆轮。首次需要图像时才初始化 EGL 渲染。

## 模型与资源

`model.cpp` 使用 libxml2 读取 `assets/robot.xml`，并在内存中建立对战 MJCF。它复制机器人刚体和驱动，并为名称添加前缀。模型保留原始 CAD 网格，设置碰撞掩码，并加入物理偏航与俯仰伺服、标定相机、枪口点和竞赛尺寸的发射管。

两台机器人各有四块相机可见的 `3` 号标签。标签外侧的纹理方向已修正。运行时不需要生成 XML 文件或调用 Python 辅助程序。

原始模型与数据来源保存在 `assets` 中，包括 `assets/rm_auto_aim/LICENSE` 和 `source.json`。数字预处理和旋转滤波沿用归档实现中来源于 MIT 许可代码的算法。OpenCV DNN 直接执行原始 ONNX 权重。

## 感知与控制

检测器通过 RGB 通道差值提取敌方灯条。几何配对结果进入标定后的 IPPE 平面 PnP。ONNX 分类器拒绝空白、低置信度和不适用的小装甲编号。系统使用已知安装倾角及像素重投影消除法向歧义。世界坐标变换只使用观察方自己的相机位姿和编码器。

11 维 Eigen 扩展卡尔曼滤波器估计车心位置、速度、偏航、角速度、交替装甲半径及高度差。编号门限、考虑协方差的新息检查、装甲关联和跟踪超时共同阻止过期观测触发自动开火。检测器与滤波器均不接收敌方仿真坐标。

瞄准预测包含装甲旋转、重力和继承的枪口速度。物理伺服限制角速度，并使用速度前馈。自动射击要求预测装甲朝向枪口，且瞄准误差落在以米计的窗口内。

弹丸对运动盒体、椭球和圆柱执行扫掠相交检查。车体命中会吸收弹丸。只有装甲外侧接触且相对速度超过阈值时才计入伤害。命中去抖、100 ms 冷却、热量保护、过热锁定、无敌模式和重置行为均沿用旧版规则。

## 原生进程接口

每行请求是一个 JSON 对象。例如：

```json
{"command":"settings","args":{"auto_fire":true}}
```

成功响应使用 `{"ok":true,"result":...}`。错误响应使用 `{"ok":false,"error":"..."}`，且不终止进程。

支持 `state`、`tick`、`reset`、`pause`、`settings`、`drive`、`aim`、`fire` 和 `frame`。图像视角为 `scene`、`camera`、`raw`、`number`。响应中的 `mime` 为 `image/jpeg`，`data` 为 Base64 数据。场景画面支持全景和跟随视角。弹丸与轨迹叠加由原生渲染器完成。

设置名称和默认值与网页一致。目标移速和转速均默认为 2，范围均为 0～4。`invulnerable` 默认为 `true`。标量类型错误、非有限数和越界命令会整条拒绝，不会只修改部分设置。显式传入布尔值时，重复 `pause` 请求保持同一状态。

驾驶指令在 350 ms 墙钟时间后失效。服务还会拒绝排队期间过期的请求，并通过内部字段 `_drive_ttl_ms` 传递剩余有效期，范围为 0～350 ms。独立 RPC 默认有效期为 350 ms。手动瞄准接受 ±6.28 rad 的偏航角和 ±0.45 rad 的俯仰角。

## 验证

`duel_behavior` 覆盖热量边界、冷却、扫掠几何、旋转滤波收敛、切板、交替几何、协方差、错误编号、丢失与重获。它还覆盖真实 ONNX 推理、合成 RGB/PnP、非法命令、控制默认值、暂停，以及基于接触的装甲伤害和无敌模式。

`duel_render` 使用真实 EGL/MuJoCo 像素，贯通 ONNX、PnP、滤波、100 Hz 瞄准射击和物理判定。它检查四种 JPEG 画面、失观停火、重置、车轮侧移和旋转目标跟踪。它还检查八块外侧标签方向、不可读标签不能初始化跟踪，以及墙钟看门狗和服务传入的有效期能阻止过期驾驶。

2026-10-08，本机使用 MuJoCo 3.15.0 和 OpenCV 4.12.0，通过两组 CTest。真实渲染闭环在 0.4 s 首次开火。0.8 rad/s 旋转场景在 110 帧中跟踪了 107 帧，末段角速度估计中位数为 0.74892 rad/s。测试包含实际装甲伤害。这些数据来自测量，不能视为实车精度保证。
